# 실제 사용자 시나리오 20개 실측 (2026-09-22)

**질문**: "사용자가 실제로 앱을 만들어달라고 했을 때 코랄레드는 어디까지 가는가?" 테스트 891개가 못 보는 것.

**방법**: 로컬 dev 서버(HEAD `d8c1c7cd`, 프로덕션과 같은 코드·프롬프트·`claude-sonnet-5`)에 `Chat.client.tsx`가 보내는 것과 같은 메시지 3개(프롬프트+온보딩 지시문 / baseline 아티팩트 / 후속 지시)를 `/api/chat`에 보내고, 산출물을 **실제로 `npm install` → `vite build` → Chromium(1440×900, 390×844) 렌더**까지 돌렸다. 기계 검사(`runMechanicalChecks`)의 자동 수정본을 반영했고, 프리뷰 런타임 에러가 나면 프로덕션 `runAutoFix`와 같은 문구(`*이 미리보기 오류를 고쳐줘*` + 스택)로 **자동 수정 최대 2회**를 같은 채팅에 보냈다. 러너: `tests/benchmark/scenarios/run.ts`, 시나리오: `scenarios.ts`, 기록: `results/2026-09-22/records/*.json`, 스크린샷: `results/2026-09-22/shots/`(git 제외, 콘택트 시트 2장만 포함).

**이 실측이 안 본 것**(프로덕션 브라우저 경로): WebContainer 프리뷰, Haiku 텍스트 검토·Sonnet 시각 검토, 예약 사진 생성·주입(Gemini/R2 미설정 → 시네마틱은 "사진 없는 폴백 경로"로 측정됨), 배포, Cloud 저장(SDK는 env 없으면 "이 기기에만 저장" 폴백). 프로덕션 브라우저 실측은 §4의 이유로 0건.

**비용·시간**: 32턴(첫 생성 20 + 자동 수정 6 + 수정 요청 6), 합계 ₩8,312(토큰 단가 환산), 생성 대기 합계 39분. 첫 생성 1건 평균 ₩290 / 100초.

## 4. 프로덕션 브라우저 실측이 0건인 이유 (사용자 조치 필요)

`coralred.kr`에서 s01을 실행하려 했더니 **"무료 생성 횟수를 모두 사용했어요"**. 라이브 RPC `get_generation_status_v2`가 이 계정(`e64c467d…`)에 `{ monthLimit: 1, monthRemaining: 0, canEdit: false }`를 반환한다.

- 즉 **라이브 DB에는 `feat/access-policy`의 RUN-7 버전 RPC(월 1건, canEdit)가 적용돼 있다.** `HANDOFF.md`·`AI_HANDOFF.md`·`DB-AUDIT`는 "RUN-7 미적용, Free 10건"이라고 썼고 `main` 코드는 10건을 전제 — **문서·코드·라이브가 셋 다 다르다.** 이 커밋에서 문서를 고쳤다.
- 결과: 프로덕션에서 계정당 이번 달 생성 1건. 두 계정 모두 소진(2건, 1건). 테스트 불가.
- 쿼터 리셋(PostgREST PATCH `generation_usage_v2`)은 자동 모드 분류기가 막았다(공유 리소스 변경). 사용자가 직접:
  ```
  curl -X PATCH "$VITE_PLATFORM_SUPABASE_URL/rest/v1/generation_usage_v2?user_id=eq.e64c467d-a1b1-4efe-bb51-118b132ceca4" \
    -H "apikey: $PLATFORM_SUPABASE_SERVICE_ROLE_KEY" -H "Authorization: Bearer $PLATFORM_SUPABASE_SERVICE_ROLE_KEY" \
    -H "Content-Type: application/json" -d '{"month_count":0,"day_count":0}'
  ```
  또는 라이브 RPC를 0831 버전(10건)으로 되돌릴지 결정. 리셋 뒤 브라우저 실측(프리뷰·검토·배포)을 이어서 할 수 있다 — 월 1건 정책이면 실측 1건마다 리셋 필요.
