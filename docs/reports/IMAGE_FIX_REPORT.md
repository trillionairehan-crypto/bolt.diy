## 1. 어느 파일의 어떤 지시를 뭐로 바꿨는지

### 조사 결과 — 실제로 쓰이는 프롬프트 파일 특정
`app/lib/common/prompts/` 아래에는 프롬프트가 3개 있습니다 (`prompt-library.ts`에서 관리):
- **`new-prompt.ts`** — "Default Prompt". 사용자가 설정 화면에서 직접 바꾸지 않는 한
  **모든 사용자가 실제로 쓰는 프롬프트**입니다 (`api.chat.ts` → `stream-text.ts`가
  `promptId || 'default'`로 이 프롬프트를 불러옵니다).
- `prompts.ts` — "Old Default Prompt" (레거시, 설정에서 수동 선택해야만 쓰임)
- `optimized.ts` — "Optimized Prompt (experimental)" (실험용, 설정에서 수동 선택해야만 쓰임)

세 파일 다 "Pexels 스톡 사진을 항상 쓴다"는 지시를 담고 있었지만, 이번 작업은 지시대로
**실제로 쓰이는 파일(`new-prompt.ts`)만** 고쳤습니다. 나머지 둘은 §3에 남겨둔 이유로
일부러 손대지 않았습니다.

### `new-prompt.ts`에서 바꾼 곳 2군데

**① `<technology_preferences>` 섹션 (요약 지시 한 줄)**
- 전: "Coralred ALWAYS uses stock photos from Pexels (valid URLs only). NEVER downloads images, only links to them."
- 후: 외부 스톡 이미지 URL 삽입 금지 + 사용자가 사진을 첨부/요청했을 때만 실제 사진 사용 +
  없으면 placehold.co 플레이스홀더 사용, 자세한 내용은 `<design_instructions>` 섹션 참고하라는
  안내로 교체.

**② `<design_instructions>` → "Design Principles" 섹션 (상세 디자인 지침)**
- 전: "스톡 이미지가 필요하면 Pexels에서만 가져와라(Unsplash 금지)"는 문장 1개
- 후: 4개 문장으로 교체
  1. **사진 없이 완성되는 디자인을 기본값으로 삼는다** — 색(`--hue`), 타이포그래피, 여백,
     디자인 키트의 CSS 패턴(`.cr-card`, `.cr-section` 등), 아이콘, 이모지로 브랜드를 표현하라고 명시.
     "사진이 없어도 완성돼 보이는 것"을 목표로 못 박음 (참고 못 채운 빈자리가 아니라).
  2. **외부 스톡 이미지 URL 삽입 금지** — AI가 사진 내용을 검증할 수 없어서 맥락에 안 맞거나
     깨진 이미지가 뜬다는 이유를 명시. 대신 커스텀 일러스트/3D 요소/심볼릭 비주얼 사용 권장(기존 문구 유지).
  3. **실제 사진은 사용자가 채팅에 첨부했거나 명시적으로 요청했을 때만** — 그 외에는
     `placehold.co` 플레이스홀더 + "여기에 원하는 사진을 넣어 주세요" 같은 한국어 안내 문구를 넣도록 지시.
  4. **로고는 텍스트 워드마크 또는 인라인 SVG** — 로고에 외부 이미지 URL 사용 금지 (새로 추가한 규칙, 기존엔 없었음).

기존에 있던 "이 디자인 키트는 배경에 그라데이션·글로우를 금지한다"는 규칙(같은 섹션의 바로 다음 줄)은
그대로 뒀고, 새로 쓴 문장에서도 "그라데이션을 대안으로 써라"고 하지 않았습니다 — 지시 원문(사진 대신
그라데이션 사용)을 그대로 따르면 이 코드베이스의 기존 디자인 키트 규칙과 정면으로 모순되기 때문에
의도적으로 뺐습니다.

## 2. 브라우저 확인 방법

1. `pnpm run dev`로 개발 서버를 켠다 (또는 이미 켜져 있으면 그대로).
2. **새 채팅**을 열고, 사진이 자연스레 들어갈 법한 앱을 하나 만들어 달라고 요청한다
   (예: "습관 트래커 앱 만들어줘", "카페 홈페이지 만들어줘").
3. 결과물 코드를 확인:
   - `unsplash.com`, `pexels.com`, `images.pexels.com` 같은 외부 사진 URL이 코드 어디에도
     없어야 한다 (있으면 실패).
   - 히어로 섹션이나 카드에 사진이 있어야 할 법한 자리에 사진이 없거나, 있다면
     `placehold.co` URL과 "여기에 원하는 사진을 넣어 주세요" 같은 한국어 안내가 함께 있어야 한다.
   - 로고 자리에 이미지 URL이 아니라 텍스트 로고 또는 SVG 코드가 있어야 한다.
4. 미리보기 화면에서 실제로 열어봐서, 사진 없이도 화면이 허전해 보이지 않고 색·타이포그래피·
   아이콘만으로 완성도 있게 보이는지 확인한다.
5. (선택) 채팅에 이미지를 직접 첨부한 뒤 "이 사진을 써서 만들어줘"라고 요청 — 이 경우엔
   첨부한 이미지를 실제로 활용하는지 확인한다 (이 경로는 이번에 막지 않았음).

## 3. 일부러 안 한 것과 이유

- **`prompts.ts`(레거시 "Old Default Prompt")와 `optimized.ts`(실험용 프롬프트)는 그대로 뒀습니다.**
  둘 다 여전히 "Pexels 스톡 사진을 써라"는 옛 지시를 담고 있지만, 사용자가 설정 화면에서
  일부러 이 두 프롬프트로 바꾸지 않는 한 절대 쓰이지 않습니다. 지시사항이 "실제 사용 중인 파일을
  조사해서 특정"하라고 했고, 그 파일은 `new-prompt.ts` 하나였습니다. 안 쓰이는 파일까지 넓혀서
  고치는 건 이번 작업 범위(최소 변경) 밖이라 판단했습니다. 나중에 이 두 프롬프트도 정리하고
  싶다면 알려주시면 같은 원칙으로 고칠 수 있습니다.

- **스타터 템플릿(Astro/Next.js/Vite 등 기본 뼈대)에는 손댈 하드코딩된 스톡 이미지가
  없었습니다.** `unsplash.com`/`pexels.com` 문자열로 저장소 전체를 검색했지만 아무것도
  안 나왔습니다 — 이유는 스타터 템플릿들이 이 저장소 안에 파일로 있는 게 아니라
  `app/utils/constants.ts`에 등록된 **외부 GitHub 저장소**(`xKevIsDev/bolt-vite-react-ts-template`
  등)에서 매번 새로 내려받는 방식이기 때문입니다. 이 세션에서 다른 사람 소유의 외부 저장소를
  수정할 수는 없으므로, 이 부분은 손대지 못했습니다 — 스톡 이미지가 있다면 그쪽 저장소를
  따로 고쳐야 합니다.

- **채팅에 이미지를 첨부하는 기존 기능 자체는 건드리지 않았습니다.** 사용자가 사진을 직접
  주는 경로는 이미 있던 기능이고, 이번 작업은 "AI가 마음대로 스톡 사진을 박아넣는 것"만
  막는 게 목적이었습니다.

- **한국어 로컬라이징, 카카오/Supabase/결제 관련 지시 등 다른 섹션은 지시대로 전혀 건드리지
  않았습니다.**

- **`app/routes/pricing.tsx`는 열지도, 건드리지도 않았습니다.**

- **프롬프트 캐싱 스냅샷을 고정해둔 테스트(`new-prompt.spec.ts`)를 확인했지만, 사진/Pexels
  관련 문자열을 검사하는 테스트는 하나도 없어서 갱신할 게 없었습니다** — 스토리지 모드
  전환(cloud/supabase) 관련 어서션만 있고, 이번 변경으로 캐시 프리픽스의 구조(마커 위치 등)
  자체는 그대로라 전체 테스트(vitest 451개)도 수정 없이 그대로 통과했습니다.
