# 모바일 전용 레이아웃 신설 — 완료 보고서

작업일: 2026-08-27
브랜치: `overnight5`
커밋: `cc4b8be`(새 모바일 화면 구현) / `0abbff7`(옛 모바일 코드 정리)

---

## 배경 — 왜 다시 고쳤는지

좁은 화면에서 채팅과 작업화면(워크벤치)이 겹치는 문제를 이전에 세 번(커밋 `5f7746b`, `d2d99c3` 포함)
고쳤지만, 실제 기기에서 여전히 증상이 재현됐습니다. 세 번의 수정 모두 "데스크톱의 좌우 분할
레이아웃 위에 좁은 화면용 예외 처리를 덧붙이는" 방식이었는데, 이 방식 자체가 겹침·쌓임 순서(z-index)
경쟁이 구조적으로 계속 발생할 수밖에 없는 구조였습니다.

이번엔 방식을 바꿨습니다: **좁은 화면(1024px 미만)에서는 데스크톱 레이아웃과 워크벤치를 아예
화면에 그리지 않습니다.** 대신 처음부터 모바일 전용으로 설계된, 완전히 별도의 화면을 그립니다.
겹칠 레이어 자체가 없으니 겹침 문제가 구조적으로 발생할 수 없습니다.

## 1. 모바일에서 이제 뭐가 보이는지 (화면 흐름 순서대로)

**전제**: 아래 내용은 채팅을 시작한 뒤(첫 메시지를 보낸 뒤)부터 적용됩니다. 첫 화면(코랄레드 소개
랜딩 페이지)은 이번 작업 대상이 아니라서 예전 그대로입니다.

**① 상단 헤더**
- 왼쪽: 사이드바 열기 아이콘 + 작게 줄인 로고
- 가운데: 지금 만들고 있는 앱의 제목(채팅 이름)
- 오른쪽: "배포하기" 버튼 하나만. 테마(밝기) 전환 버튼, Supabase 연결 버튼, 디버그 도구는 모바일
  헤더에 없습니다.

**② 화면 본문 — 하단 탭 2개로 전환**
- **[대화] 탭**: 기존 채팅 화면(메시지 목록 + 입력창)이 화면 전체 폭을 씁니다. 데스크톱과 똑같은
  채팅 컴포넌트를 그대로 재사용했습니다 — 새로 만든 채팅 로직은 없습니다.
- **[미리보기] 탭**: 만들고 있는 앱이 화면 전체를 씁니다. 아직 만든 게 없으면 "앱을 만들면 여기서
  바로 볼 수 있어요"라는 안내가 뜹니다.
- 두 탭은 동시에 그려지지 않습니다 — 한 번에 하나만 화면에 있습니다(겹칠 레이어 자체가 없음).

**③ AI가 응답을 마치면 뜨는 카드**
- "누르면 미리보기가 열려요"라는 문구의 카드가 채팅 안에 뜹니다(데스크톱에서는 "누르면 작업 화면이
  열려요"). 누르면 하단 탭이 자동으로 [미리보기]로 바뀝니다.

**④ 코드/차이점/파일 목록/터미널**
- 모바일에서는 이 화면들로 들어갈 방법이 아예 없습니다(버튼도, 탭도 없음) — 지시대로 진입 경로
  자체를 없앴습니다.

**⑤ 사이드바(대화 목록)**
- 기존과 완전히 동일합니다. 헤더의 사이드바 아이콘을 누르면 예전 그대로 열립니다 — 이 부분은
  손대지 않았습니다.

## 2. 실기기 체크리스트 (coralred.kr 기준)

휴대폰으로 coralred.kr에 접속해서 확인하세요 (화면 폭 약 375~430px 기준).

1. **채팅 시작 전** — 기존 랜딩 페이지가 예전과 똑같이 보이는지 확인 (이번엔 안 건드림).
2. **아무거나 만들어 달라고 요청** (예: "습관 트래커 앱 만들어줘").
   - [ ] 상단 헤더에 로고(작게), 앱 제목, "배포하기" 버튼만 보이는지. 테마 버튼이나 다른 버튼이
     안 보여야 정상.
   - [ ] 화면 맨 아래에 [대화]/[미리보기] 탭바가 보이는지.
   - [ ] AI가 답변을 쓰는 동안 채팅 글자가 온전히 보이고, 뒤에 다른 화면이 비쳐 보이지 않는지.
3. **AI 응답 안의 "누르면 미리보기가 열려요" 카드를 눌러본다.**
   - [ ] 하단 탭이 자동으로 [미리보기]로 바뀌고, 만든 앱 화면이 전체 폭으로 보이는지.
   - [ ] 아직 미리보기가 없는 시점에 미리 탭을 눌러보면 "앱을 만들면 여기서 바로 볼 수 있어요"
     안내가 보이는지.
4. **하단 탭바에서 [대화]를 다시 눌러본다.**
   - [ ] 채팅 화면으로 완전히 돌아오고, 이전 대화 내용이 그대로 보이는지.
5. **"배포하기" 버튼을 눌러본다.**
   - [ ] (미리보기가 준비된 상태에서) 배포 메뉴가 정상적으로 열리는지 — 데스크톱과 같은 배포
     기능을 그대로 재사용했습니다.
6. **헤더의 사이드바 아이콘을 눌러본다.**
   - [ ] 대화 목록 사이드바가 예전과 똑같이 열리는지.
7. **화면을 가로로 돌리거나(가로모드), 태블릿처럼 좀 더 넓은 화면으로 테스트해본다면**:
   - [ ] 1024px를 넘는 순간 데스크톱 레이아웃(좌우 분할, 코드/차이점 탭 포함)으로 자연스럽게
     바뀌는지 확인.
8. **iOS(아이폰) 사파리에서 특히 확인**: 미리보기가 실제로 로딩되고 동작하는지. (아래 §4의 조사
   내용 참고 — iOS 16.4 이상이어야 미리보기 엔진이 정상 동작합니다.)

## 3. 데스크톱 회귀 확인 체크리스트

브라우저 폭을 1024px 이상(예: 1440px)으로 넓혀서 확인하세요.

- [ ] 채팅을 시작하면 예전처럼 화면 왼쪽에 채팅, 오른쪽에 작업화면(워크벤치)이 좌우로 나란히
  뜨는지 확인 (탭바 방식으로 바뀌면 안 됨 — 그건 모바일 전용).
- [ ] 헤더에 로고, 앱 제목, 테마 전환 버튼, Supabase 연결, 배포하기 버튼이 예전처럼 전부 보이는지.
- [ ] "누르면 작업 화면이 열려요" 카드(모바일과 문구가 다름)를 누르면 예전처럼 작업화면이
  좌우 분할로 열리는지.
- [ ] 코드/차이점/미리보기 탭 전환, 파일 목록, 터미널 열기가 예전과 똑같이 동작하는지.
- [ ] 채팅 숨기기 버튼, 되돌리기(체크포인트) 메뉴, 파일 저장, 내보내기 버튼이 예전과 똑같이
  동작하는지.
- [ ] 코드를 작성하는 동안 작업화면이 자동으로 열리고, 미리보기가 준비되면 자동으로 미리보기
  탭으로 넘어가는 기존 동작이 그대로인지.

## 4. 정리한 이전 코드 / 일부러 안 한 것

### 정리한(삭제한) 이전 코드
이전 세 번의 "겹침 수정" 시도에서 만든 코드는 이제 전부 쓰이지 않게 됐습니다 — 워크벤치 컴포넌트
자체가 좁은 화면에서는 아예 화면에 그려지지 않기 때문입니다. 그래서 별도 커밋(`0abbff7`)으로
다음을 지웠습니다:
- `Workbench.client.tsx`의 좁은 화면 전용 코드 전부 (전체화면 배치, 최우선 겹침 순서(z-max) 설정,
  툴바 가로 스크롤 처리, 열릴 때 미리보기 탭으로 자동 전환하던 로직) — 이 파일이 원래(이번 세션이
  시작되기 전) 가지고 있던, 더 오래된 좁은 화면 처리 코드까지 포함해서 전부 제거했습니다.
- `app/utils/workbenchMobileLayout.ts`와 그 테스트 파일 — 더 이상 아무도 부르지 않아서 삭제.

### 일부러 안 한 것
- **WebContainer(미리보기 엔진)가 모바일 브라우저, 특히 iOS 사파리에서 도는지 조사만 하고 고치진
  않았습니다** (지시대로). 조사 결과: iOS 16.4부터 사파리에서도 미리보기가 정상 지원됩니다
  ([StackBlitz 공식 발표](https://blog.stackblitz.com/posts/webcontainers-are-now-supported-on-safari/)).
  이 앱은 미리보기에 필요한 보안 헤더(Cross-Origin-Opener-Policy/Cross-Origin-Embedder-Policy)를
  `app/entry.server.tsx`에서 이미 모든 페이지에 걸어두고 있어서 별도 설정 없이도 조건은 충족돼
  있습니다. 다만 **큰 프로젝트는 모바일 기기의 메모리 제약 때문에 느려지거나 멈출 수 있다**는
  경고가 공식 문서에 있습니다 — 오늘은 손대지 않았고, 실제로 문제가 되는지는 §2 체크리스트로
  실기기에서 확인해봐야 압니다.
- **레이아웃 라이브러리를 새로 넣지 않았습니다.** 새 의존성 없이 기존 nanostore/React 패턴만
  썼습니다.
- **채팅 로직 자체는 한 줄도 다시 안 짰습니다.** `Messages`/`ChatBox`는 기존 것을 그대로 재사용
  했고, 채팅 쪽 코드에서 바뀐 건 "화면을 어떻게 감쌀지"뿐입니다.
- **`Preview` 컴포넌트 내부(주소창, 기기 크기 선택기 등 데스크톱 지향 툴바)는 모바일용으로 따로
  단순화하지 않았습니다.** 지시에 없던 개선이라 손대지 않았고, 그대로 재사용했습니다 — 필요하면
  별도 작업으로 다듬을 수 있습니다.
- **`useViewport` 훅의 서버 렌더링(SSR) 크래시 가능성은 이번에 직접 고쳤습니다** (지시 밖 버그가
  아니라, 이번 기능이 이 훅을 새로 쓰면서 바로 발생하는 문제였기 때문입니다) — `BaseChat.tsx`는
  서버에서도 한 번 그려지는 컴포넌트라, 고치지 않았다면 서버 오류로 이어졌을 수 있습니다. 자세한
  내용은 `useViewport.ts`의 커밋 메시지에 적어뒀습니다.
- **`app/routes/pricing.tsx`는 열지도, 건드리지도 않았습니다.**
- **레이아웃(실제 화면에 겹침이 없는지, 탭이 정확히 눌리는지)은 자동 테스트로 검증할 방법이
  없습니다** — 이 저장소의 기존 관례대로(컴포넌트 렌더링 테스트 인프라 없음), vitest 전체
  통과·빌드 성공·타입 에러 없음까지만 자동으로 확인했고, 최종 확인은 §2의 실기기 체크리스트로
  직접 해주셔야 합니다.
