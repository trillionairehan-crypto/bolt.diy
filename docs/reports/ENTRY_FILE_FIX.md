## 원인

### 1) 스타터 템플릿(Vite React)의 진입 파일 구성
`app/utils/constants.ts`의 `STARTER_TEMPLATES` 목록엔 "Vite React"(라벨: "React + Vite +
typescript", 저장소 `xKevIsDev/bolt-vite-react-ts-template`) 하나만 있고, TypeScript
기반입니다. 코랄레드 자체 "기본값"(사용자가 특정 템플릿을 안 고르거나 GitHub 템플릿
가져오기가 실패했을 때, `app/utils/selectStarterTemplate.ts`의 `getBaselineTemplate`)도
`src/main.tsx`가 `import App from './App.tsx'`를 쓰고, 같이 시드되는 `src/App.tsx`도
TypeScript입니다 — **이 둘은 항상 같이 만들어지는 우리 쪽 코드라 서로 어긋날 일이
없습니다.**

### 2) 생성 프롬프트의 확장자 지시
`new-prompt.ts`를 전체 검색한 결과, **`.jsx`라는 단어는 파일 전체에 단 한 번도 등장하지
않습니다.** `.tsx`/entry 관련 문구는 `<artifact_instructions>`의 한 줄
("the entry component must be src/App.tsx")이 유일한데, 이 문장은 사실 "React Native
앱 구조를 만들지 마라"는 경고문 한가운데 곁다리로 끼어 있던 것이었습니다(문맥은 온통
`app/_layout.tsx`, `app.json` 금지 얘기). 즉 **"파일 확장자를 섞이게 유도하는 문구"는
없었지만, "이미 있는 진입 파일의 확장자를 그대로 유지해야 한다"는 문구도 없었습니다** —
지시가 섞이게 만든 게 아니라, 지시가 애초에 없었던 공백이었습니다.

### 3) 왜 main.tsx는 그대로 두고 App.jsx를 만드는 패턴이 생기는가
템플릿/베이스라인이 이미 `src/main.tsx` + `src/App.tsx`를 심어둔 뒤, 모델은 실제
사용자 요청 내용을 채우기 위해 "이어서 계속 작업하라"는 후속 턴을 받습니다. 이때
프롬프트는 "이미 있는, 안 고쳐도 되는 파일은 건드리지 마라"고만 하고, "App을 다시 쓸
땐 반드시 같은 파일 경로·확장자를 그대로 써라"는 말은 없었습니다. 모델이 실제 앱
내용을 작성하며 습관적으로(학습 데이터에서 흔한 "React 앱 = .jsx" 패턴) 새 파일을
`App.jsx`로 만들면, `main.tsx`는 "안 고쳐도 되는 파일"이라 손대지 않고 그대로 두게
되고, `main.tsx`가 이미 갖고 있던 `import App from './App.tsx'`는 더 이상 존재하지
않는 파일을 가리키게 됩니다. **결론: 확장자를 섞이게 만드는 지시가 있었던 게 아니라,
"진입 파일은 새로 만들지 말고 기존 파일을 그 자리에서 고쳐 써라"는 지시가 빠져 있던
것이 원인입니다.**

### 4) 프로덕션 빌드가 실제로 깨지는가 — **깨집니다 (직접 재현 확인)**
로컬에서 정확히 같은 상황(`src/main.tsx`가 `import App from './App.tsx'`를 쓰는데
`src/App.tsx`는 없고 `src/App.jsx`만 있는 상태)을 실제 Vite 프로젝트로 재현해서
`vite build`(코랄레드가 생성하는 앱의 `package.json`에서 `"build": "vite build"`로 정의된
바로 그 명령)를 직접 돌려봤습니다:

```
[31mx[39m Build failed in 134ms
error during build:
Could not resolve "./App.tsx" from "src/main.tsx"
```

**종료 코드 1, 빌드 실패.** 미리보기가 관대해서 화면이 뜨는 것처럼 보이는 이유도 같이
확인했습니다 — 개발 서버(`vite`)에 직접 요청을 보내봐도 `index.html`은 200으로 정상
응답하지만(정적 파일이라 모듈 해석과 무관), `main.tsx` 자체는 **500 에러**를 내며 Vite의
에러 오버레이를 반환합니다. 즉 "화면 자체는 뜬다"는 건 배경/틀(HTML)만 뜨고 실제
리액트 앱은 마운트되지 않은 채 에러 오버레이가 얹혀 있는 상태였지, 미리보기가 실제로
이 문제를 눈감아준 게 아니었습니다 — 개발 서버도 프로덕션 빌드도 똑같이 실패합니다.
**심각도는 확인하신 우려대로 높습니다.**

## 조치

가장 유력한 원인(2·3번)에 맞춰 **한 곳만** 고쳤습니다 — `new-prompt.ts`의 기존
entry-file 지시문(`<artifact_instructions>`) 한 줄에 아래 내용을 추가:

> `src/main.tsx`와 `src/App.tsx`가 이미 있으면(템플릿 가져오기나 코랄레드 베이스라인이
> 이미 만들어둔 것) **그 파일들을 정확히 같은 이름·확장자로 그 자리에서 내용만 교체**한다.
> 기존 파일 옆에 다른 확장자의 진입 컴포넌트(예: `src/App.jsx`)를 새로 만들지 않는다 —
> main.tsx의 기존 import는 그대로 원래 파일을 가리키므로 새로 만든 파일은 아예 안
> 쓰이게 되고, **이건 미리보기만의 사소한 문제가 아니라 실제 `vite build` 실패**라고
> 명시했습니다.

템플릿/후처리기 쪽은 건드리지 않았습니다(추측으로 여러 곳을 동시에 고치지 말라는
지시에 따름) — `file-reference-postprocess.ts`(import 정합성 검증기)는 코드를 읽어본
결과 이미 정확히 의도대로 동작하고 있었습니다: `App.tsx`처럼 확장자가 명시된 import는
정확히 그 경로에 파일이 있는지만 확인하고(다른 확장자로 자동 보정하지 않음), 없으면
정확하게 "없다"고 잡아내서 자동수정(auto-fix) 흐름으로 넘깁니다. 즉 **사후 감지·복구는
이미 제대로 작동 중**이었고, 문제는 애초에 불일치가 생기는 걸 막는 사전 지시가
없었다는 점이었습니다 — 그래서 이번 수정은 사전 지시를 채우는 쪽으로만 했습니다.

## 재현 확인 방법

배포 후, 아래 두 신호로 확인해주세요:

1. **간단한 재현**: "카페 포인트 적립 앱처럼 아주 단순한 앱을 만들어줘" 같은 프롬프트로
   2-3회 생성해보고, 이번에도 "파일이 없어요"(App 관련) 오류·자동복구가 뜨는지 확인.
   이번 수정이 먹혔다면 이 오류 자체가 안 떠야 합니다.
2. **의심되면 직접 확인**: 생성된 앱의 `src/main.tsx`가 정확히 어떤 파일을 import하는지,
   `src/` 폴더에 `App.tsx`와 `App.jsx`가 동시에 존재하는지(있으면 안 됨) 워크벤치
   파일 탐색기에서 눈으로 확인.
3. 그래도 재발하면, `file-reference-postprocess.ts`의 자동수정이 여전히 잡아서
   복구는 되지만(전에 확인한 대로 정상 동작 중), 처음부터 안 생기게 막는 이번 수정이
   부족하다는 뜻이니 알려주시면 템플릿 처리 쪽(후속 턴 안내 문구)도 검토하겠습니다.
