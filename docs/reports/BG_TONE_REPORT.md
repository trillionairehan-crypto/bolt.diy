## 조사 결과 — 원인은 "hue가 틀려서"가 아니라 "채도가 거의 0이라서"였습니다

배경 크림이 정의된 곳을 전부 찾아본 결과:

- **`app/styles/variables.scss`** — 코랄레드 화면(채팅, 헤더, 사이드바 등)이 실제로 쓰는 색상표.
  `--bg`/`--surface`/`--surface-2`가 이미 `oklch(밝기 채도 var(--hue))` 형식으로, 코랄 강조색과
  **같은 색조 값(hue: 33)을 쓰고 있었습니다.** 문제는 채도가 0.001~0.002(사실상 0)로 너무 낮아서,
  hue가 코랄과 같아도 눈에는 그냥 무채색(회색에 가까운 흰색)으로 보였던 것입니다. 특히
  `--surface`는 채도가 아예 `0`(순백)이었습니다.
- **`uno.config.ts`** — 색상을 직접 정의하지 않고 위 `variables.scss`의 값을 이름만 연결해주는
  파일이라, 고칠 게 없었습니다.
- **`design-handoff/coralred-ui.css`** — 이건 코랄레드 화면이 아니라 **AI가 만들어주는 사용자 앱들이
  기본으로 쓰는 디자인 키트**입니다. 확인해보니 여기도 똑같은 문제(채도가 거의 0)가 있었지만,
  이번 지시는 코랄레드 자체 화면에 관한 것이라 **일부러 손대지 않았습니다** — 자세한 이유는
  아래 4번에 적었습니다.
- 사용자분이 말씀하신 `#FAF7F2`라는 정확한 값 자체는 코드 어디에도 없었습니다 — 기존 `--bg` 값을
  그대로 계산해보면 `#fbfaf9`이 나오는데, 이건 눈으로 보고 스포이드로 짚었을 때 거의 똑같은 색으로
  보였을 값입니다. 그러니까 "`#FAF7F2`가 어디 박혀 있다"가 아니라, **`--bg` 토큰 자체가 그렇게
  보였다**는 뜻으로 이해하고 그 토큰을 고쳤습니다.

## 1. 어디를 어떤 값으로 바꿨는지

`app/styles/variables.scss`의 라이트 테마(밝은 화면) 색상표에서 4곳을 바꿨습니다. hue(색조)는
그대로 33(코랄과 동일)을 쓰고, **채도만 소폭 올렸습니다** — 밝기 순서(surface가 제일 밝고,
surface-2, bg 순으로 살짝 톤이 있음)는 그대로 유지했습니다.

| 토큰 | 이전 | 이후 |
|---|---|---|
| `--bg` (페이지 배경) | `oklch(0.985 0.002 33)` ≈ `#fbfaf9` | `oklch(0.97 0.01 33)` ≈ `#fcf3f1` |
| `--surface` (카드/패널) | `oklch(1 0 0)` = 순백 `#ffffff` | `oklch(0.995 0.006 33)` ≈ `#fffcfb` |
| `--surface-2` (보조 표면) | `oklch(0.995 0.001 33)` ≈ `#fefdfd` | `oklch(0.985 0.008 33)` ≈ `#fff8f7` |
| `--auth-page-bg` (로그인 화면 배경) | 하드코딩 `#faf7f0` (hue 약 88 — 코랄과 더 안 맞았음) | `var(--bg)`로 통일 |

**참고**: 사용자분이 예시로 주신 `#FCF4EC`는 hue가 약 68(노란빛이 도는 따뜻한 색)인데, 코랄 강조색
자체는 hue가 33(주황-빨강 쪽)입니다. 지시하신 대로 "hue를 33에 맞추는" 방식으로 갔기 때문에,
`#FCF4EC`를 그대로 복사한 것과는 살짝 다르게 — **노란 크림보다는 옅은 코랄/살구빛에 가까운
톤**으로 나왔습니다. 이게 원하시던 방향이 맞는지 §4 체크리스트로 직접 봐주시고, 혹시
"더 노란 크림 쪽이 좋겠다" 싶으시면 채도 값(현재 0.01/0.006/0.008)을 그대로 두고 hue만
조정하는 방식으로 쉽게 다시 조절할 수 있습니다.

## 2. 함께 조정한 표면 목록

`--bolt-elements-*` 토큰 대부분이 `--bg`/`--surface`를 그대로 참조하고 있어서(`var(--bg)`,
`var(--surface)`), 위 4곳만 고쳐도 자동으로 같이 따뜻해집니다:
- 채팅 메시지 영역 배경 (`--bolt-elements-bg-depth-1`)
- 카드/패널류 (`--bolt-elements-bg-depth-2`, 아티팩트 카드, 액션 박스, 프롬프트 입력창, 터미널
  배경 등 — 전부 `var(--surface)` 참조)
- 로그인/회원가입 페이지 전체 배경 (`--auth-page-bg` → `var(--bg)`로 통일)

**순백(`#FFFFFF`)이 남아서 뜨던 곳**: `--surface` 토큰 자체가 정확히 이 문제였습니다 — 고쳤습니다.

## 3. 되돌리는 방법

`app/styles/variables.scss`의 `:root, :root[data-theme='light']` 블록에서 아래 4줄을 예전 값으로
되돌리면 됩니다 (다크모드 블록은 이번에 전혀 안 건드렸으니 그대로 둡니다):
```css
--bg: oklch(0.985 0.002 var(--hue));
--surface: oklch(1 0 0);
--surface-2: oklch(0.995 0.001 var(--hue));
--auth-page-bg: #faf7f0;
```

## 4. 확인할 화면 목록

밝은 화면(라이트 모드, 현재 기본값)에서 확인해주세요.

- [ ] **첫 화면(랜딩 페이지)** — 코랄 히어로 섹션 아래, 흰 배경 영역들의 톤이 코랄과 잘 어울리는지.
- [ ] **채팅 화면** — 메시지 배경, 내가 보낸 말풍선 주변 배경이 예전보다 살짝 더 따뜻해 보이는지.
- [ ] **워크벤치가 열렸을 때 미리보기 패널의 테두리/배경**.
- [ ] **로그인 / 회원가입 페이지** — 전체 배경 톤 (이번에 `--bg`와 통일됐습니다).
- [ ] **사이드바(대화 목록)** — 배경과 카드들.
- [ ] **글자가 읽기 편한지** — 직접 눈으로도 확인해주시면 좋고, 계산으로는 대비가 이전
  17.4:1에서 16.6:1로 사실상 변화가 없었습니다(권장 기준 4.5:1~7:1보다 훨씬 여유 있음).
- [ ] **다크모드로 강제 전환해서(개발자 모드에서 `DARK_MODE_ENABLED`를 잠깐 켜보는 등) 다크
  화면이 이번 변경과 무관하게 예전 그대로인지** — 다크 테마 토큰은 안 건드렸습니다.

## 발견했지만 손대지 않은 것

- **`design-handoff/coralred-ui.css`(AI가 만드는 사용자 앱들의 기본 디자인 키트)에도 똑같은
  "채도가 거의 0" 문제가 있습니다.** `variables.scss`의 코드 주석에는 "이 두 파일이 공식까지
  똑같이 맞춰져 있어야 한다"고 적혀 있어서 서로 짝이 맞는 파일인 건 확인했지만, 이번 지시는
  코랄레드 자체 화면(채팅/헤더/로그인 등)에 관한 것이었고, 이 키트를 바꾸면 **앞으로 만들어지는
  모든 사용자 앱의 기본 배경색이 다 같이 바뀝니다** — 훨씬 큰 범위의 변경이라 이번엔 건드리지
  않았습니다. 원하시면 같은 방식(hue 33 유지, 채도만 소폭 상향)으로 별도 작업할 수 있습니다.
