## 1. 문제 1 — 미리보기 탭에 앱이 안 뜨던 문제

### 원인은 (a)였습니다 — 단, 짐작했던 것과는 조금 다른 지점이었습니다

**결론**: MobileWorkspace의 미리보기 탭 자체는 처음부터 올바른 데이터(`workbenchStore.previews`)를
정확히 구독하고 있었습니다 — 데스크톱 워크벤치와 완전히 같은 방식으로 연결돼 있었습니다. 그런데
실제로 확인해보니 **"연결이 안 된" 진짜 대상은 미리보기 화면이 아니라, 앱을 실제로 만드는 작업
(npm install, npm run dev를 실행하는 부분) 자체**였습니다.

코드를 하나하나 따라가 보니:
- AI가 만든 코드로 실제 `npm install`/`npm run dev`를 실행하는 건 브라우저 안에서 도는 가상 컴퓨터
  (WebContainer)의 "셸(shell)"입니다.
- 이 셸은 **터미널 화면(사용자에게 보이는 콘솔 창)이 화면에 나타나야만 비로소 "준비 완료" 상태가
  됩니다.** 코드 규칙상, 명령어를 실행하는 모든 곳이 "셸 준비될 때까지 기다린다"는 코드를 갖고
  있는데, 이 "준비" 신호가 오직 터미널 화면 컴포넌트가 화면에 나타날 때만 켜지도록 돼 있었습니다.
- 그런데 **모바일 화면은 이번 v2 작업에서 데스크톱 워크벤치(터미널 화면을 포함해서)를 아예 그리지
  않기로 설계**했습니다 — "코드/차이점/파일트리/터미널 진입 경로 없음"이라는 요구사항 그대로요.
- 그 결과 모바일에서는 이 "준비 완료" 신호가 영원히 안 켜졌고, `npm install`/`npm run dev` 명령이
  **조용히 영원히 멈춰있는 상태**가 됐습니다. 앱이 실제로는 한 줄도 안 만들어지고 있었으니
  미리보기가 뜰 수 없었던 것입니다 — "미리보기 탭 연결이 안 된 것"이 아니라 "만들어지는 앱 자체가
  없었던 것"이었습니다.

이건 오늘 확실히 고칠 수 있는 문제였고(WebContainer가 모바일 브라우저에서 아예 못 뜨는 문제가
아니었으므로), 그래서 (b)가 아니라 (a)로 판단하고 고쳤습니다.

### 조치
사용자에게 보이는 터미널 화면을 모바일에 새로 추가한 게 아닙니다 — 대신 **화면에는 안 보이지만
저 "준비 완료" 신호만 켜주는 아주 작은 터미널 부품 하나**를 모바일 화면에 몰래(숨김 상태로)
같이 넣었습니다. 사용자는 이걸 볼 수도, 조작할 수도 없습니다 — 순수하게 "셸을 깨우는" 용도입니다.
데스크톱은 원래도 터미널 화면(사용자에게 안 보이는 상태로도)이 항상 같이 그려지고 있었기 때문에,
이번 조치는 모바일도 데스크톱과 똑같은 상태로 맞춘 것뿐입니다.

## 2. 문제 2·3에서 뭘 바꿨는지

### 문제 2 — 모바일 글씨·여백 축소
- 채팅 메시지 본문 글씨 크기를 모바일에서만 14px로 줄였습니다 (이 앱이 이미 쓰고 있는 "작은 글씨"
  기준값과 같은 숫자입니다 — 마음대로 고른 숫자가 아닙니다). 제목(h1~h6)은 이 본문 글씨 크기에
  비례해서 정해지는 구조라, 이거 하나만 바꿔도 제목들도 같이 작아집니다.
- 줄간격, 문단·목록·표 사이 여백도 모바일에서만 비례해서 줄였습니다.
- 메시지와 메시지 사이 간격, 내가 보낸 말풍선의 안쪽 여백도 모바일에서만 줄였습니다.
- **1024px 이상(데스크톱)에서는 전부 예전 값 그대로**입니다 — 코드에서 "모바일에서만" 조건을
  걸어서 처리했습니다.
- 입력창(76px)과 하단 탭바(약 60px)는 이미 충분히 커서(44px 이상) 손대지 않았습니다.

### 문제 3 — 헤더 겹침·잘림 + 랜딩 다크모드 토글
- **진짜 원인**: 채팅 제목이 길면 자동으로 "..."으로 줄여야 하는데, 그 처리가 제대로 안 걸려있는
  코드 구조상의 버그를 찾았습니다. 로고/제목/배포하기 버튼이 겹쳐 보이거나 잘려 보인 건 "화면이
  좁아서"가 아니라, 애초에 제목 글자가 자기 자리를 벗어나 양옆으로 삐져나오고 있었기 때문입니다.
  그 원인 부분을 고쳐서 이제 긴 제목은 자리에 맞게 "..."으로 줄어들고, 로고나 배포하기 버튼과
  겹치지 않습니다. (이 버그는 데스크톱에도 똑같이 있었지만, 화면이 넓어서 지금까지 눈에 띄지
  않았을 뿐입니다 — 그래서 모바일 전용 조건 없이 근본 원인 자체를 고쳤습니다.)
- 랜딩(첫 화면) 헤더의 다크모드(테마) 전환 버튼을 모바일 화면 폭에서 숨겼습니다. 데스크톱에서는
  그대로 보입니다.

## 3. 실기기 체크리스트 (coralred.kr, 안드로이드 크롬 기준)

1. **새 채팅에서 앱을 하나 만들어 달라고 요청한다.**
   - [ ] AI가 "만드는 중이에요"를 거쳐 응답을 마치고, 잠시(빌드 시간) 기다린 뒤 하단 탭에서
     [미리보기]를 누르면 **이번엔 실제로 만든 화면이 보여야 한다** — 이게 이번 수정의 핵심입니다.
   - [ ] "누르면 미리보기가 열려요" 카드를 눌러도 마찬가지로 실제 화면이 보이는지 확인.
2. **채팅 메시지 화면을 확인한다.**
   - [ ] 이전보다 글씨가 작아지고, 한 화면에 더 많은 내용이 들어오는지 확인.
   - [ ] 그래도 글자가 너무 작아서 읽기 힘들 정도는 아닌지 확인 (읽기 편한 수준으로 판단해주세요).
   - [ ] 내가 보낸 말풍선, AI 답변 사이 간격이 예전보다 좁아졌는지 확인.
3. **채팅 상단 헤더를 확인한다.**
   - [ ] 채팅 제목이 길 때 로고나 "배포하기" 버튼과 겹치지 않고 "..."으로 줄어드는지 확인 (제목을
     길게 지어보고 테스트하면 더 확실합니다 — 예: "정말정말정말 긴 이름의 프로젝트 제목 테스트").
4. **첫 화면(로그인 전 랜딩 페이지)을 확인한다.**
   - [ ] 헤더에 다크모드(테마) 전환 버튼이 더는 안 보이는지 확인.
5. **입력창과 하단 탭바를 눌러본다.**
   - [ ] 손가락으로 누르기 불편할 정도로 작아지지 않았는지 확인 (이 둘은 일부러 안 줄였습니다).

## 4. 데스크톱 회귀 확인 (참고)

브라우저 폭 1024px 이상에서:
- [ ] 메시지 글씨 크기, 줄간격, 여백이 예전과 완전히 같은지.
- [ ] 헤더 레이아웃(로고, 제목, 테마 토글, 배포하기 등)이 예전과 같은지.
- [ ] 랜딩 페이지 헤더에 다크모드 토글이 그대로 보이는지.
- [ ] 워크벤치(작업화면) 열기, 미리보기, 터미널 등 기존 기능이 전부 그대로 동작하는지.

## 참고 — 지시 밖이라 손대지 않은 것
- **"전송/만들기" 버튼(`SendButton.client.tsx`)의 높이가 32px로, 손가락 터치 기준(44px)보다
  작습니다.** 이번에 새로 생긴 문제가 아니라 원래부터 있던 상태이고, 이번 지시("입력창·탭바는
  44px 이상 유지")의 대상이 아니라서 손대지 않았습니다. 필요하시면 별도 작업으로 키울 수 있습니다.
- **`Preview` 컴포넌트 내부의 데스크톱 지향 툴바(주소창, 기기 크기 선택기 등)** 는 지난 보고서에
  이어 이번에도 손대지 않았습니다.
